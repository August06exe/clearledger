# 指标口径清单 v1

> 口径铁律：每个指标只有一个定义处（当前在 dbt 模型 SQL + 本文档），报表层只能引用、不能重算。
> 将来的指标中心（语义层）即从本文档 + `int_sales_enriched.sql` 演化而来。

## 基础口径（唯一出处：`int_sales_enriched.sql`）

| 指标 | 定义 | SQL |
|------|------|-----|
| 订单金额（折前） | 数量 × 实际成交单价 | `gross_amount` |
| **收入** | 订单金额 × (1 − 折扣率) | `net_amount` |
| **成本** | 数量 × 商品标准成本 | `cost_amount` |
| **毛利** | 收入 − 成本 | `gross_profit` |

- 折扣率缺失视为 0（清洗规则，见 `stg_sales.sql`）
- 标准成本来自商品主数据（`stg_products.std_cost`），是毛利口径的基准

## 费用分摊（唯一出处：`int_expense_alloc.sql`）

| 规则 | 内容 |
|------|------|
| 销售事业部费用 | 直接归属其负责区域 |
| 总部/职能部门费用 | 按**各区域当月收入占比**分摊到区域 |
| 兜底规则 | 该月全公司零收入时按**区域数均摊**（总部费用绝不静默蒸发） |
| 区域费用 | = 事业部直接费用 + 分摊来的总部费用 |

> 分摊逐行四舍五入到分，与原费用可能存在分位级尾差；如需绝对平账（对账场景），在 v0.4 口径引擎中引入最大余量法。

## 数据完整性骨架

- `mart_kpi_monthly` / `mart_region_month` 使用**日历月 × 区域骨架**：某区域某月零销售也成行（收入记 0），
  环比永远基于上一日历月，不会跳月、不会缺行。
- 客户 LTM（`mart_customer_summary`）= 最近 **12 个完整月**，部分月不计入。

## 汇总指标（唯一出处：marts 层）

| 指标 | 出处 | 定义 |
|------|------|------|
| 净利 | `mart_kpi_monthly` | 毛利 − 分摊费用 |
| 毛利率 | `mart_kpi_monthly` | 毛利 / 收入 |
| 净利率 | `mart_kpi_monthly` | 净利 / 收入 |
| 收入环比 | `mart_kpi_monthly` / `mart_region_month` | 本月 / 上一日历月 − 1（零销售月补 0，绝不跳月） |
| LTM 收入 | `mart_customer_summary` | 最近 12 个完整月收入 |

## 数据质量规则（红绿灯）

| 灯 | 触发 | 实现 |
|----|------|------|
| 🔴 红 | 摄取失败，或 dbt 失败/无本轮产物，或任一模型/测试 error/fail | 下游被拦截，报表页显示"数据过期"横幅，Excel 导出首行警示 |
| 🟡 黄 | 区域收入环比骤降 > 50%（排除未走完的当月） | `assert_region_revenue_mom_stable.sql` (severity=warn) |
| 🟡 黄 | 销售流水最近订单日距今 > 3 天（疑似断更） | `assert_sales_data_fresh.sql` (warn) |
| 🟡 黄 | 公司毛利率超出 [0, 1]（完整月） | `assert_margin_sane.sql` (warn) |
| 🟡 黄 | 折前金额 ≠ 数量×单价（口径漂移校验） | `assert_amount_matches_qty_price.sql` (warn) |
| 🟡 黄 | 折扣率超出 [0, 1] | `assert_discount_rate_range.sql` (warn) |
| 🟡 黄 | 负数量 / 未来订单 / 负收入 | `assert_sales_values_sane.sql` (warn) |
| 🟡 黄 | 清洗层剔行超过 1%（源文件质量恶化对账） | `assert_stg_sales_row_loss.sql` (warn) |
| 🔴 红 | 销售事业部未声明负责区域（费用归属会丢） | `assert_sales_dept_has_region.sql` (error) |
| 🟢 绿 | 全部通过 | — |

**约定：当月是"部分月"**——KPI 卡与报表默认只统计**完整月**（`month < date_trunc('month', current_date)`），
部分月的当日数据在 marts 中保留，供日报类报表未来使用。

## 投放区数据契约（data/inbox/）

新数据源按 `ingest/sources.yml` 声明的表头投放；表头变更会显式报错（防止静默错数）。
当前 5 个源：销售流水（CSV/UTF-8 或 GBK）、客户主数据（XLSX）、商品主数据（XLSX）、组织架构（CSV）、部门费用（XLSX）。

# 附：契约违规统一账本与规则词表 v2（2026-09-21，R1 评审归因后钉死）

## 契约违规统一账本（raw.contract_report）

所有数据质量违规的**唯一留痕处**，挂起队列（门户「配置工作台→挂起队列」）即读此表最近一次 run：

| 违规来源 | rule 词表 | 写入时机 | level 语义 |
|---|---|---|---|
| 字段契约-类型 | `type` | 摄取期逐行统计（值不可解析，行保留置 NULL） | 字段 level（默认 yellow） |
| 字段契约-必填 | `required` | 摄取期（该行剔除，sample 为描述性文本） | 字段 level |
| 字段契约-范围/枚举/格式 | `range` / `enum` / `format` | 摄取期逐行统计（行保留） | 字段 level |
| 字段契约-唯一键 | `unique` | 摄取期 | 恒 red |
| 入口档案问题 | `file_missing` / `header_changed` / `empty_file` / `multi_match` / `row_drop_ratio` / `type_coerce_ratio` | 摄取期 | problems 配置定级 |
| 匹配契约 | `fanout` / `null_match` / `orphan_right` | **跑批收获**（dbt 测试结果，source=宽表声明名，cnt=dbt failures；null_match 为去重未匹配值数） | 测试 severity（warn→yellow，error→red） |

## 语义 v2 要点（2026-09-21 评审归因后修订）

1. **两阶段校验**：先在原始帧全量记录违规（先记录后动作）——同 row 多违规不互相掩盖；再统一执行 required 剔行与类型化。
2. **剔行语义**：仅 required 违规剔行（产品原则"入库即干净字段"）；type 违规行保留（置 NULL 交由 missing 策略/下游处理）；raw 行数 = 文件数据行数 − required 剔行数。
3. **sample 一律非空**（required 填描述性文本）。
4. **报表分层（base 级联）**：分层 mart 从上级 mart 卷聚合，上级自动携带后代指标所需可加列（sum 逐层重聚合）；分组维度后代传导；比率指标每层由可加部分重算、不做比率求和。规则词表与勾稽要求随 R2 密封口径演进。
