# 决策：落地实施方案（从可交互原型到真实数据验证）

> 2026-09-25。起因：原型已完成（工作台/分层/勾稽/瀑布图），准备接入真实企业数据验证。
> 用户的顾虑：直接在主项目文件夹里干容易乱套，过程必然反复拉扯。本文档给出环境分离方案与实施节奏。

## 一、核心判断

三条原则，全部来自行业常规做法（环境分离、私有部署区、反馈分诊），按明账的现状裁剪：

1. **公开仓库永远不碰真实企业数据**。真实数据、真实公司口径（里面全是客户名、项目名、经营语义）只存在于私有实施区。公开仓库继续只放演示数据与引擎。
2. **试点跑打 tag 的稳定版，不追开发前沿**。试点要的是可复现——这周跑的是 v0.5-beta，修了 bug 发 v0.5.1 再升级；开发线继续往前走，互不拖累。
3. **功能开发冻结，转入验证窗口**。时间智能、分摊引擎、闸门 R4~R6 全部排队。原因：在没有真实数据反馈时继续堆功能，是在给猜测加码。试点第一批摩擦回来之后，这些排队项的优先级要重新排（比如分摊引擎可能因为真实费用分摊需求提前，时间智能可能因为试点根本没提而延后）。

## 二、目录结构（平级三区）

```
D:\Workshop\3000-Projects\
├── 3005-DA-AI Native数据底座系统\   ← 开发区（公开 GitHub 仓库）
│   只放引擎、门户、演示数据、测试契约。真实数据永远不进这里。
│
├── 3006-明账试点-影子客户\          ← 模拟试点（影子客户演练场，已在用）
│
└── 3010-明账实施-<公司简称>\        ← 实施区（新建，私有）
    ├── 产品副本\                    ← 从 GitHub Releases 的 tag 下载解压（不是 git clone）
    ├── instances\company\           ← 真实六份配置（含公司业务语义，私有）
    ├── data\                        ← 真实企业数据（投放区 + warehouse）
    ├── 任务书.md 需求清单.md 试点日志.md
    └── （整个 3010 没有 .git——没有 push 通道就没有泄漏通道）
```

要点：

- 3010 **删掉 .git**。它不是开发仓库，是客户现场部署。产品升级 = 从 GitHub Releases 下载新 tag 的 zip，覆盖产品目录（instances、data 天然隔离，不受影响）。想回滚就换回旧 tag 的包。
- 备份纪律：每次跑批后跑备份数据.bat；每周把 3010 整个目录压一份到移动盘或网盘。
- 3006（影子客户模拟）保留，作为"发布前练兵场"：新版本先让影子客户跑一场，没事再进 3010。

## 三、版本与升级节奏

| 通道 | 内容 | 谁用 |
|---|---|---|
| develop 分支 | 开发前沿，随时变 | 只有开发区（3005） |
| GitHub Releases（tag，如 v0.5-beta.1） | 稳定版打包 + 启动器 exe | 3010 实施区、试点 clone |
| main 分支 | 验收过的正式版 | 公开门面 |

修复流程：3010 发现缺陷 → 需求清单 → 3005 开发线修复 → 打新 tag → 3010 覆盖升级 → 数据无感。

## 四、反馈分诊（反复拉扯的解药）

试点期"反复拉扯"是正常且健康的——问题不在拉扯，在没有分诊纪律。每一条摩擦进需求清单，标四类：

| 分类 | 去向 | 响应节奏 |
|---|---|---|
| 缺陷（数据错/崩溃/口径错） | 当场修，发新 tag | 24 小时内 |
| 可用性（能做但别扭） | backlog，攒一批改 | 每周清一次 |
| 功能缺口 | 决策包排队，重排优先级 | 试点结束后统一排 |
| 口径争议（数字对不对） | 停下，业务拍板后再动 | 不设时限，口径争议高于进度 |

红线沿用：数据不编造，红灯不硬洗。试点期发现的问题如果暴露引擎设计缺陷（像勾稽护栏测试期那样），升级为设计层讨论，不当场打补丁。

## 五、排队项处置

| 排队项 | 处置 |
|---|---|
| 时间智能 | 冻结，等试点反馈（若试点高频要环比，优先级提前） |
| 分摊引擎 | 冻结，等试点反馈（真实分摊规则样本是最好的设计输入） |
| v0.6 闸门 R4~R6 | 冻结；试点稳定后在新状态上验收（新特性应被测试覆盖） |
| 真实数据试点 | **立即启动**——这就是验证本身 |

## 六、启动清单（3010 首日）

1. 建 `3010-明账实施-<公司简称>/`，从 Releases 下载 v0.5-beta.1 产品包解压
2. 把真实数据文件放进 data/inbox（先拷贝原件，原件另外保存不动）
3. 新开对话（工作目录指到 3010），点火词："读取 任务书.md 严格执行"——任务书里写清楚业务背景、要交的报表、数据位置
4. 会计 agent 用装配线体检（R-11）起草六份配置 → 人工审一遍口径 → 跑批 → 看灯
5. 每天收工把摩擦记进 试点日志.md；每攒一批回 3005 分诊一次
