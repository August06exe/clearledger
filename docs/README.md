# 明账文档地图

本目录是明账 ClearLedger 的公开文档区。四份编号文档按阅读顺序排列，本页是总入口。

## 编号文档（按序读）

| 编号 | 文档 | 写给谁 | 内容 |
| --- | --- | --- | --- |
| 01 | [点火指南](01-点火指南.md) | AI 代理（或照做的普通人） | 全新环境自举：克隆 → 依赖 → 演示数据 → 门户可访问，含验收清单与首跑故障 |
| 02 | [操作手册](02-操作手册.md) | AI 代理（日常操作者） | 系统地图、配方 R-01~R-14（含无损升级 R-14）、故障 playbook、红绿灯语义 |
| 03 | [指标口径](03-指标口径.md) | 业务与财务人员 | 指标口径基础域定义；各账套口径以 `instances/<账套>/metrics.yml` 为唯一出处 |
| 04 | [产品路线图](04-产品路线图-投资人版.md) | 外部读者 | 版本演进与产品主张 |

`assets/` 存放文档引用的图片（logo、截图、信息图）。

仓库根目录另有四份非编号文档，各有固定用途，不进编号序列：`README.md`（项目主页）、`AGENTS.md`（AI 工程章程，代理接管入口）、`UPGRADE.md`（逐版本升级须知，配合 `ops/upgrade.py` 使用）、`VERSION`（当前版本号，一行纯文本）。

## 仓库结构导览

按"谁读它"分组，编号只是导览顺序，目录本身不重命名。

**对外门面（仓库根）**

1. `README.md` / `README.en.md` — 项目主页（中英）
2. `AGENTS.md` — AI 代理接管入口：30 秒认知、红线、快速命令
3. `UPGRADE.md` + `VERSION` + `upgrade-manifest.example.json` — 升级三件套：须知、版本号、manifest 模板
4. `LICENSE`、`requirements.txt`、`openapi_keys.example.json` — 协议、依赖清单、API 钥匙模板

**引擎与接口（换项目不改的部分）**

5. `semantic/` — 语义引擎七件套：加载校验、摄取、编译、查询、收获、体检。零业务预设，口径只认账套配置
6. `mcp_server.py` — stdio MCP 只读接口（六只工具，供外部 AI 助手查账）

**门户（人看的界面）**

7. `app/` — FastAPI 后端 + 原生 JS 前端（`app/static/`），仅本机监听 8620

**账套与数据（一个公司一个包间）**

8. `instances/<账套>/` — 每账套六份 yml 配置 + 投放区 + 生成的 dbt 管道（`pipeline/models` 为生成物，禁手改）
9. `sample_data/` — 演示数据生成脚本（数据本身不进仓库）
10. `data/`（运行时，不入库）— 各账套 DuckDB 金库、跑批历史、备份、密钥

**运维工具**

11. `ops/` — 体检仪 `doctor.py`、启动器 `launcher.py`、备份 `backup.py`、升级协议 `upgrade.py`（+`upgrade_common.py` 公共件）
12. `备份数据.bat`（双击备份薄壳）、`启动明账.exe`（启动器成品，不进 git，从 Releases 下载）

**质量与文档**

13. `tests/` — 测试体系：`tests/upgrade/` 单测与升级演练（日常跑），`tests/v0.4~v0.6/` 为三权分立密封套件（动它们之前先读 `AGENTS.md` 红线）
14. `docs/` — 本目录

**本地与内部（不入公开仓库）**

15. `.venv/`、`logs/`、`_trash/` — 环境、日志、退役资产暂存
16. `internal/` — 内部档案（决策台账、迭代日志、设计稿、交接文档），索引见 `internal/docs/README.md`

## 维护规则

- 新公开文档加入本目录：取下一个可用编号（当前用到 04），文件名 `编号-名称.md`，并在本地图登记一行
- 改名或移动已有文档：先全局搜索引用并同步修改（`git grep 旧文件名`）；`tests/` 下的密封套件引用历史名称，属冻结证据，不追改
- 写给 AI 的操作文档保持"配方"体例：一条配方 = 一件事 + 完整命令 + 判定标准
