# 设计：v0.5 配置工作台（Config Workbench）

> 状态：设计定稿（2026-09-20 夜，随夜航实现）
> 本文档是 v0.5 验收测试的**命题依据**：API 契约、语义、错误类、安全边界全在此。
> 命题 Agent 只依据本文档与现有配置样例独立推导答案，禁读实现。

## 1. 背景与范围

明账的一切业务变化收敛于每账套的六份 YAML 配置，而配置目前只能靠 agent/编辑器手改。
v0.5 在门户内提供「配置工作台」：**看配置、校验草稿、保存生效（自动重编译重跑）、查看挂起队列、预览影响**。
GUI 与 AI 同源双入口——界面的每个动作，等价于 agent 改文件 + 跑三步链。

**做**：六块配置的读取/草稿校验/保存（含备份与触发重建）、挂起队列查询、影响预览。
**不做**（后续版本）：表单化结构化编辑、版本 diff/回滚 UI、内嵌 AI 问答、permissions.yml（v0.7 才有此文件）。

## 2. 可编辑块与文件映射

| block | 文件 | 说明 |
|---|---|---|
| `instance` | `instance.yml` | 账套元信息（title/inbox/database） |
| `sources` | `sources.yml` | 入口档案 + 字段契约 |
| `wide` | `wide.yml` | 关联 + 派生列 |
| `dimensions` | `dimensions.yml` | 维度声明 |
| `metrics` | `metrics.yml` | 口径唯一出处 |
| `dashboard` | `dashboard.yml` | 报表声明 |

白名单**封闭**：上表之外的 block 一律 404。`permissions.yml` 目前不存在于任何账套——请求它也是 404。

## 3. API 契约（全部挂 `/api/config` 前缀）

错误类约定（与门户现有约定一致）：实例目录不存在 → **404** `{"detail": ...}`；
block 不在白名单或文件不存在 → **404**；保存时校验不过 → **422** `{"ok": false, "errors": [...]}`，**绝不落盘**；
请求体缺 `content` 或非字符串 → **422**。所有响应 JSON。

### 3.1 GET `/api/config/{instance}` —— 概览
```json
{"instance": "sales", "title": "演示销售公司",
 "blocks": [{"block": "sources", "file": "sources.yml", "size": 4123, "mtime": "...", "exists": true}, ...六块按上表顺序...]}
```
`mtime` 为 ISO 本地时间。配置不合法**不影响**本端点（列表只看文件）。

### 3.2 GET `/api/config/{instance}/{block}` —— 读原文
```json
{"instance": "sales", "block": "metrics", "file": "metrics.yml",
 "content": "<原始YAML文本>", "parsed_ok": true, "parse_error": null}
```
YAML 解析失败也返回 200：`parsed_ok: false` + `parse_error` 为异常消息首行——**看坏文件不该 500**。

### 3.3 POST `/api/config/{instance}/{block}/validate` —— 草稿校验（绝不写盘）
请求：`{"content": "<草稿YAML>"}`。
响应 200：`{"ok": true|false, "errors": ["..."], "warnings": ["..."]}`。
校验层次（按序，全部通过才算 ok）：
1. YAML 语法解析（safe_load）；
2. 必须是映射（dict）；
3. **交叉校验**：把草稿替换该块、其余五块取磁盘现状，组装成完整实例走引擎加载器的全部校验
   （缺必需键/join 引用悬空/维度列不在宽表/指标公式引用断链/报表引用不存在的指标或维度等——
   以加载器实际报错为准，错误消息原文进 `errors`）。
校验不产生任何文件副作用（含 mtime）——这是行为测试点。
`warnings` 当前恒为空数组（占位，未来放 lint 类提示）。

### 3.4 POST `/api/config/{instance}/{block}/save` —— 校验→备份→原子写→可选重建
请求：`{"content": "<新YAML>", "rebuild": false}`（rebuild 缺省 false）。
流程：校验（同 3.3，不过 → 422 不落盘）→ 把磁盘上旧文件复制到
`instances/<instance>/onboarding/config_history/<block>.prev.yml`（**固定路径单份滚动备份**）→
临时文件 + 原子 replace 写入 → 若 rebuild=true 触发该账套三步链（触发器标记 `"workbench"`）。
响应 200：
```json
{"ok": true, "block": "metrics", "backup": "instances/sales/onboarding/config_history/metrics.prev.yml",
 "affected_reports": ["region_month", "category_month"],
 "rebuild": {"triggered": true, "run_id": "...", "reason": null}}
```
- `affected_reports`：影响预览（见 §5）。精确语义（保守口径）：
  - block=`metrics` → 新草稿中**出现的任一指标名**（按名匹配，不管公式是否变化，新增也算）被哪些报表引用的并集，升序；
  - block=`dashboard` → 新草稿中定义的**全部报表 key**，升序；
  - 其余块恒为 `[]`。
  - 与 §3.6 impact 端点共享同一推导逻辑。
- rebuild 触发失败（如已有跑批在跑，互斥）→ 保存仍成功，200 + `rebuild: {"triggered": false, "run_id": null, "reason": "run_in_progress"}`。
- 下划线前缀实例（`_wb_*` 测试副本约定）同样可寻址可保存——工作台直连目录，不过正式账套清单过滤。

### 3.5 GET `/api/config/{instance}/pending` —— 挂起队列
读该账套 DuckDB `raw.contract_report` **最近一次 run_id** 的全部行。
```json
{"instance": "retail", "latest_run": {"run_id": "...", "finished_at": "...", "light": "yellow"},
 "items": [{"source": "fact_ledger", "field": "quantity", "rule": "range", "level": "pending", "cnt": 3, "sample": "..."}, ...],
 "note": null}
```
- **稳定投影**：items 只含 `(source, field, rule, level, cnt, sample)` 六字段，按 `(source, field, rule)` 升序——
  `ts`/run_id 不进 items（跨双跑可逐字节比对）。
- `sample` 为信息性文本，只要求非空字符串（口径：`sample` 参与比对时用"非空"类，不做逐字节比对）。
- 无库文件 → 200 + `{"items": [], "latest_run": null, "note": "no_db"}`。
- 表不存在/空 → `items: []`。
- `problems` 类行（文件缺失等）field 为 `"-"`，同样进 items。

### 3.6 GET `/api/config/{instance}/impact` —— 影响预览
纯配置推导，不碰引擎：
```json
{"instance": "sales",
 "metrics": {"销售额": ["monthly_kpi", "region_month"], "毛利": ["monthly_kpi"]},
 "dimensions": {"大区": ["region_month"], "月份": ["monthly_kpi", "region_month"]}}
```
- 指标 → 引用它的报表 key 列表（报表的 `metrics` 数组）；
- 维度 → 引用它的报表 key 列表（`dimension` + `filters` + `time_dim` 三处并集）；
- 两者均按 key 升序；未被引用的指标/维度映射到 `[]`。

## 4. 安全与并发

1. **实例名防穿越**：`instance` 路径参数必须匹配 `^[A-Za-z0-9][A-Za-z0-9_\-]*$` 且解析后目录必须位于
   `instances/` 之下——`../`、绝对路径、嵌套路径一律 404，绝不落盘到 instances 之外。
2. **块白名单封闭**（§2），无通配。
3. **原子写**：临时文件写成功后 `os.replace`；写失败不留半个文件。
4. **备份**：每次覆盖前先把旧文件复制到 `onboarding/config_history/<block>.prev.yml`（滚动单份；恢复靠 git 或此备份）。
5. **互斥**：重建触发走既有 dbt_runner 全局互斥；工作台保存本身不持锁（保存的是 YAML 文本，与跑批读库无竞争）。

## 5. 前端「配置工作台」页

- 左侧六块列表（含文件大小/mtime），右侧编辑器（monospace textarea）+ 「校验」「保存」「保存并重建」三按钮。
- 校验结果面板：ok 绿 / errors 红列表逐条展示。
- 挂起队列子页：表格式列出 items（源/字段/规则/级别/次数/样例），红黄 chip 着色。
- 影响预览：保存 metrics/dashboard 时，响应里的 affected_reports 以 toast + 面板展示"本次改动影响 N 张报表"。
- 静态资源版本号照纪律升级（`?v=` 串）。

## 6. 测试隔离与基线恢复（给命题/测试的约定）

1. 测试一律用 **`_wb_r<N>` 前缀测试实例**（`instances/_wb_r1/`…）：工作台可寻址、不出现在正式账套清单（既有约定）。
2. 基线 = 测试实例目录的文件副本；恢复 = 删目录重拷。官方四账套任何文件不得被测试改动（行为测试点）。
3. 对象类型 = SaaS/API 预设：答案 = 每请求的 status + body 稳定投影；基线恢复 = 文件副本；服务重启即可复测。
4. 确定性承诺：pending 稳定投影、save 后 GET 回读、impact 全部是同输入双跑逐字节一致（除 mtime/时间戳字段，已排除在比对面外）。

## 7. 变异体菜单（装备校正 ≥3，bug 类声明——具体补丁由被测方实现后提供）

| id | bug 类（SPEC 级声明） | 装备必须抓住 |
|---|---|---|
| M1 | **保存绕过校验**（save 不校验直接写） | B-保存非法草稿必须 422 且文件不变 |
| M2 | **挂起队列丢级**（pending 端点漏掉某 level 的行） | 数值 Case：挂起 items 与密封答案逐行比对 |
| M3 | **白名单/防穿越失效**（任意 block 或路径可写） | B-非白名单 block 404 / B-穿越尝试拒绝且无越界写 |

## 8. 非功能红线（继承全局）

口径唯一出处不变（工作台只是 metrics.yml 的另一个编辑入口）；marts 只读不变；
生成物不手改不变（保存触发的是重编译，不是改 models）；`data/`、`logs/` 不入 git 不变。
