## 第一性原则：AI-Native

本产品的一切设计从这条原则推导，与"用 AI 辅助开发的传统工具"有本质区别：

1. **系统的第一读者和第一操作者是 AI，人类只做验收与拍板。** 维护者不需要会写代码——文档的首要读者是 AI agent（AGENTS.md / AI 操作手册 / 自检脚本三件套随每个版本交付）。
2. **一切业务形态是配置，AI 可读可写。** 不同公司的差异最终收敛为五份配置文件（数据源/宽表/维度/指标/看板）；引擎代码零业务预设、永不随客户改写。
3. **AI 是安装工。** 新公司接入 = 一次 AI 会话：读文件 → 体检 → 问答补口径 → 生成五份配置 → 机器校验 → 人审核。积木是标准的，安装是自动的。
4. **AI 的产出与人类产出同规同矩**：进 Git、过测试门禁、留运行痕迹；AI 不得为"让灯变绿"编造或绕过数据——红绿灯可信度高于一切。
5. **每个版本的验收标准里都有 AI 指标**：接入耗时、自愈闭环率、配置覆盖率（业务层写死代码占比 → 0%）。

## 一句话定位

把公司管理报表的生产，从"多人接力的人工流水线"升级为"AI 生产、自动运转的数据流水线"——并进一步成为**一套通用积木**：任何公司的管理报表，都能在小时内由 AI 装配出来，而数据从哪来、怎么加工、被谁使用，全程可追溯。

## 我们解决什么问题

传统管理报表的生产链路：业务系统导出 → 人工 Excel 加工 → 多轮传递 → 人工拼装成报表。痛点：

- **慢**：每个环节都是人工节点，出数周期以天计
- **黑盒**：口径藏在某个人脑里，"这个数怎么算的"没人说得清
- **脆弱**：一个人休假或离职，报表就断供
- **不可复制**：每家公司的报表系统都是一次性的手工作品，无法迁移给下一家

## 产品理念

1. **AI-Native 第一**（见上）
2. **一切皆代码/配置**：报表逻辑、清洗规则全部进 Git，可版本、可回滚、可审计
3. **血缘与字典是副产品**：管道每跑一次，血缘图和数据字典自动保持最新
4. **红绿灯治理**：数据异常自动亮灯、自动归因，错误数据不流进报表
5. **入库即干净**：数据进入仓库时就是规整字段，原始快照仅作底账留档

## 技术底座（一页看懂）

```
Excel/CSV/API ──摄取(清洗入库)──▶ DuckDB ──宽表装配(声明式)──▶ 语义层 ──▶ 一体化门户
                                    ▲                        (维度/指标/看板)   血缘·红绿灯·字典·报表
                                    └── 五份配置文件（sources / wide / dimensions / metrics / dashboard）
                                              ▲
                                    AI 装配线：读文件 → 问答 → 生成配置 → 校验 → 人审核
```

全开源引擎（DuckDB / dbt / FastAPI / ECharts / AntV），私有化部署，数据不出内网，未来可平滑迁云。

## 各版本详情

### v0.1「第一桶数据」✅ 已交付
- Excel/CSV 投放区接入，声明式清洗入库（DuckDB）
- dbt 三层管道 + 数据质量测试门禁，跑批红绿灯（红=失败拦截下游，报表标记"数据过期"）
- **上线标志达成**：一张报表从"人工半天"变成"机器 10 分钟自动出数"（实测全链路 8 秒）

### v0.2「看得见」✅ 已交付
- 一体化门户五页：总览红绿灯 / 血缘蜘蛛网图（含字段级下钻）/ 数据字典 / 5 张管理报表（Excel 导出）/ 跑批历史与日志
- 跑批模式可开关：默认完全手动，定时可一键开启
- 两轮独立 AI 审计 + 浏览器实测 + 故障注入测试闭环；品牌标识（"日+月=明"）
- **AI-Native 交付**：AGENTS.md（agent 接管入口）+ AI 操作手册（配方/故障 playbook/自动化 SOP）+ ops/doctor.py 自检（人类/机器双模式）
- **上线标志达成**：管理层只靠一个入口看所有数据与状态

### v0.3「通用积木」——引擎与业务彻底分离 ✅ 已交付
把"我们公司的报表"改造为"任意公司的报表平台"：业务层从写死代码变为五份配置，引擎零业务预设。
- **数据契约三层**（生产级接入的根基）：入口档案（文件名模式匹配/有序清洗管道/问题策略分级）+ 字段契约（类型/格式/范围/枚举/缺失策略）+ 匹配契约（多重匹配/匹空/孤儿等 join 异常按业务定级）
- **挂起待人工**机制：跑批第四状态——问题源挂起、他源照跑、门户待处理清单、人工裁决后 AI 沉淀为档案规则（档案=组织记忆，越用越厚）
- **契约驾驶舱（只读）**：门户配置中心 v0——入口档案/字段契约/匹配契约全景视图 + 历史违规统计 + 挂起队列处理界面
- 五份配置 schema 定稿：`sources`（数据源+入口档案）/ `wide`（声明式宽表：主表+左联标签表+派生列+匹配契约）/ `dimensions`（维度声明——筛选/分组/下钻全部由声明长出，**零预设**，不预设"客户/区域/品类"任何词）/ `metrics`（指标=公式+可选维度，口径唯一出处）/ `dashboard`（看板=卡片配置）
- 通用查询编译器：指标×维度×筛选 → SQL（白名单参数防注入）
- 双实例验证 ✅：销售公司（影子对数四项绝对差 0.0000）+ 连锁餐饮（42.8万行订单）——引擎 git diff = 0；**账套切换 ✅**：门户顶栏一键切换、全部数据 API 按账套路由、跑批器实例化（语义摄取→编译→dbt build 三步链）；旧手写管道同步退役（git 可回滚）
- **AI-Native 交付**：《语义层与多实例设计》文档（五配置+三契约+挂起机制）；AI 操作手册第 3 章配方整体重写为"配置操作"；doctor 增加五配置+契约校验项
- **上线标志**：换一家公司，只改五份配置即跑通全套门户（含血缘/字典/红绿灯）——做不到即为"仍有隐藏耦合"，回炉

### v0.4「AI 装配线」——接入自动化
- 接入 SOP 产品化：AI 读源文件 → 标准化体检报告（列/类型/空值/异常/建议维度）→ 问答补口径 → 生成五份配置 → schema 校验 → 测试门禁 → 人审核
- 配置 schema 校验器：机器审 AI 产出的第一道防线
- **开放 MCP 只读接口**（AI 的"出"，与装配线的"进"合成 AI 进出双向标准化）：四个工具——指标目录（含口径说明）/ 查报表数据 / 数据健康诊断（缺什么没导入）/ 口径查询；API 钥匙即 principal（人与钥匙统一权限底座的先行版）；只能查**已声明的维度×指标**，结构上摸不到明细行（汇总级出网由架构保证）；查询全程留痕。老板的 hermes/codex/claude code 等 MCP 客户端直连
- **AI-Native 交付**：《AI 装配 SOP》+《MCP 工具规范》进操作手册；接入耗时计量进 doctor
- **上线标志**：①全新公司的真实文件接入 < 1 小时（当前换装约一晚）②老板用自己的 agent 连明账成功完成"问数 + 诊断缺数据"两问

### v0.5「配置工作台」——配置与契约的可视化管理编辑
五配置 + 三契约从"YAML 文件（AI 的地盘）"升级为"可视化工作台（人的地盘）"，同一份事实源双入口：
- **表单化编辑**：入口档案/字段契约/匹配契约/维度/指标/看板全部表单编辑（下拉、枚举圈选、规则开关），**保存即生成 YAML 进 Git**——GUI 与 AI 对话修改走同一条路（校验→留痕→生效），单一事实源不变
- **schema 校验前置**：编辑时实时校验（引用完整性/格式/冲突），不合格保存不了
- **版本与回滚**：每次修改自动 commit + diff 视图，一键回滚到任意历史版本
- **影响预览**：改动保存前显示影响面（血缘反查：哪些报表/看板卡片会变）
- **契约驾驶舱（完整版）**：契约全景、违规趋势、挂起队列裁决界面（从 v0.3 的只读视图升级）
- **AI 随行**：工作台内嵌"问 AI"——选中任何配置项可对话修改，AI 产出同样进 diff 待确认
- **AI-Native 交付**：工作台操作 SOP 进手册；GUI 与 AI 双入口一致性测试纳入验收
- **上线标志**：一名不会 YAML 的财务，全程不碰文本编辑器，独立完成"改一个指标口径→看影响→回滚"闭环

### v0.6「复杂规则」——把"算法"管起来
- 分摊引擎（多级分摊、最大余量法平账）、组织变动后的历史重算（restatement）、自动对账 + 差异 AI 归因
- 指标高级表达式（比率/占比/窗口）
- **AI-Native 交付**：规则配置的生成与校验 SOP；对账差异自动归因报告
- **上线标志**：一次组织架构调整，历史重算全程无人工 SQL

### v0.7「多用户与权限」——第六块积木
业务单位真人接入：一个公司一套 permissions.yml，与五配置同构；引擎零预设（不内置任何角色/页面特权，引用悬空=装配期报错）。
- **统一门户纯隐藏**：所有人登录后是同一个外壳（同样的页面结构），权限的唯一作用是"未授权即不渲染"——没有"业务视图/管理视图"两个世界
- 三铁律：**锁定筛选在服务端宽表层强制**（改 URL 绕不过）、**切片打在宽表**（换报表不漏）、**默认拒绝**
- 行级（scope，$me 绑定员工编号）+ 列级（metrics deny，含可推导性校验：藏毛利率必须连收入/毛利一起藏或明示可推导）+ 筛选白名单接口同步切片
- **统一 principal**：登录用户与 API 钥匙共用同一份权限配置（承接 v0.4 钥匙底座，人机同规）
- 账号密码登录 + 自助改密码（验旧设新）+ 管理员重置；审计日志先记文件；空归属行仅管理层可见
- **前置条件**：业务侧归属数据字段（如"项目归哪个销售"，权限只能切已存在的维度）+ 常开部署（内网服务器起步）
- **上线标志**：华东销售张三登录只见自己的项目收支，且改 URL 旁路 / 下拉白名单探测 / 派生列推导三个攻击面全部无效
- **AI-Native 交付**：《权限设计文档》（permissions.yml schema + 全部推演记录）进 docs

### v1.0「正式版」——AI 自治运营
- 多实例管理（公司注册表 + 一键切换）、生产加固（权限审计界面、登录安全、备份/灾备）——承接 v0.7 权限底座
- **AI 自审常态化**：夜间无人值守审计循环（审计 agent → 修复 → 晨报），异常自愈闭环率计量
- **上线标志**：连续 30 天零人工介入出数，AI 自审发现的问题 ≥ 80% 自愈并留痕

### v1.x 长期运营（正式版后持续更新）
- 🤖 **门户内嵌 AI 助手**：对话式接数据、问数、归因——服务手里没有开发 agent 的财务客户（产品化关键一步）
- 🗣 **自然语言问数**：走语义层（NL→指标），不裸奔 NL2SQL
- 🔌 **更多数据源**：业务 API、CDC 增量同步
- ☁️ **云原生**：多租户 SaaS 化——"积木 + AI 安装工"模式的规模化形态
- 📮 **定时推送**：钉钉/企微/邮件日报

## 风险与对策

| 风险 | 对策 |
|------|------|
| 配置表达力天花板（五配置写不出某些逻辑） | 派生列留 SQL 逃生舱，但必须过测试门禁；表达力缺口回炉引擎 |
| AI 生成配置的质量 | 三道防线：schema 机器校验 → 测试门禁 → 人审核；AI 产出与人工产出同规同矩 |
| "零预设"验证失守 | 双实例是硬验收：引擎 git diff 必须为零；做不到不许发版 |
| 单人 + AI 维护的运维风险 | 极简架构（单进程+单文件库）、一键备份恢复、doctor 自检、AI 排障手册 |
| 数据安全 | 全程私有化；AI 功能默认只传表结构、不传业务明细；可选本地大模型 |
| 开源依赖风险 | 只用主流标准栈，依赖版本锁定上限 |

## 成功指标（KPI）

**业务指标**
- 报表生产人工节点：**N 个 → 0 个**
- 出数时效：T+1 达成率 **≥ 99%**（定时模式）
- 数据异常：发现时间从"几天后" → **当天亮灯 + 自动归因**

**AI-Native 指标（本产品特有）**
- 业务层写死代码占比：**→ 0%**（v0.3 验收项）
- 新公司接入耗时：**一晚 → < 1 小时**（v0.4 上线标志）
- AI 红灯自愈闭环率：**≥ 80%**（v1.0 上线标志）
- 每版本 AI 可操作性交付（手册/playbook/红线更新）：**100%**（每版验收项）
