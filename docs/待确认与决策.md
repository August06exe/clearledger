## D16：权限与开放 AI 接口设计定案（2026-09-19 讨论，已排期未开工）

**权限=第六块积木**（instances/<账套>/permissions.yml，与五配置同构）：
- 引擎零预设：只有主体（users+自定义tags）/资源（引用本账套配置已存在的页面·报表·指标·筛选，悬空=装配期报错）/权限三概念；不内置任何角色与页面特权
- **统一门户纯隐藏**：所有人同一外壳，权限唯一作用=未授权即不渲染；总览卡片/导航/报表列表全受 ACL（用户明确否决"业务视图/管理视图"两套界面）
- 三铁律：锁定筛选服务端宽表层强制（UI 锁定仅化妆）/切片打宽表/默认拒绝；筛选分 default 与 locked 两 mode
- 行级 scope（$me 按员工编号绑维度值）+列级 metrics deny+可推导性校验+筛选白名单接口同步切片
- **统一 principal**：登录用户与 API 钥匙同构共用权限配置；账号密码+自助改密码+管理员重置；审计先记文件；空归属行仅管理层；导出加水印（导出人+时间）
- 前置条件：归属数据字段+常开部署；无 permissions.yml=单用户模式（积木可拆）

**开放 AI 接口=MCP 只读门**（排入 v0.4）：四工具（指标目录含口径/查报表/数据健康诊断文件级/口径查询）；只能查声明维度×指标=汇总级出网由架构保证；API 钥匙进配置文件；只读；用户 agent=hermes/codex/claude code。

**排期**：MCP→v0.4（AI 进出双向）；权限→v0.7（v1.0 收薄为生产加固）。推演记录（张三的一天 10 坑+老板 agent 深夜提问 4 问）见讨论存档。
