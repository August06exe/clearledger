## 一、我们在哪里（现状事实）

- 「报表分层」v0 已落地（2026-09-21 凌晨）：`dashboard.yml` 报表声明 `base: 上级报表`，编译为 mart-on-mart 级联。演示账套 `ladder`（集团经营核算·利润阶梯）8 源 / 9 报表（L1 收入→L2 毛利→L2.5 费用并行→L3 贡献→L4 部门→L5 集团净利 + 侧挂 2 张）/ 52 节点全绿；L3/L4/L5 级联数值与台账直算 oracle 一致。
- **三个角色不约而同指认的四个事实缺口**（独立头脑风暴交叉验证，可信度高）：
  1. **表达式复制 6 份**：毛利/责任贡献/集团净利的损益串在 metrics.yml 逐字重抄——"口径唯一出处"红线只保证**文件**唯一，没保证**公式**唯一；改口径要人工同步 6 处，抄错即静默错报（BP、DS 各自第一痛点）。
  2. **层间零勾稽**：三层契约+dbt 测试全在输入侧，base 链没有"子层合计=父层"平衡测试；上卷丢行、NULL 桶、round 精度都可致 L3≠L4≠L5 而无人报警（ERP 顾问：这是 UAT 第一问，D12 事故同类死法）。
  3. **粒度静默变化**：L1 声明维度=项目，实际 group by 月份+项目+一级部门（后代传导）——跨部门项目拆多行，对"收入"列求和即重复计数；无声明无告警（DS 以生成物 SQL 为证）。
  4. **carry 一律 sum 无类型系统**：`avg()` 类指标或半可加列（budget_rate 已在宽表）进级联产出无意义数且零报警；比率类"每层重算"的前提（分子分母可加）零机器检查。
- 另：**字段级血缘解析**（SQLGlot 运行期）全账套失败——v0.3 生成管道迁移遗留；根治与缺口 1 同源（表达式结构化后，血缘应在编译期生成而非运行期解析）。

## 二、行业规范摘要（deepsearch）

| 来源 | 核心做法（与我们相关的部分） |
|---|---|
| dbt MetricFlow | 指标五类：simple / **derived**（引用其他指标）/ **ratio**（分子分母各自可加、查询时重算）/ cumulative / conversion；语义模型 YAML 化；指标树=派生指标 DAG |
| Airbnb Minerva | 1.2 万指标 4 千维度：**定义即配置（版本控制）、平台强制一致**；消灭"同名不同义/同义不同名" |
| Uber uMetric | 指标全生命周期 定义→计算→服务；标准化由平台层强制，不靠团队自觉 |
| SAP CO-PA | 获利能力段=**特征组合**（即我们的维度组合）；成本法/账户法两种模式；特征层级决定下钻 |
| SAP 分摊循环 | 分摊=发送方/接收方/**分摊基数**（人数/面积/收入占比）/方向/循环顺序；ABC 按动因；**分摊守恒（Σ接收=Σ发送）是硬校验** |
| Cube 多阶段计算 | 环比/累计/贡献率内置于指标定义（window/time_shift），不写裸 SQL |
| Airflow UI | 管道运行可视化三规范：**Grid（节点×历史矩阵）/ Graph（DAG 着色）/ Gantt（单次时间轴）** |

## 三、三个角色的头脑风暴（要点回放）

### 业务单位 BP（只看报表、不碰 SQL）
- 痛点：①口径"看起来唯一、其实是抄写"，月底吵架无法自证同一套口径；②报表只说"是多少"不说"好不好"——无预算、无同比环比，老板追问当场开 Excel；③数字"成色"不可见——参考图上的 ✅⚠️❌⏳（就绪/卡点/空壳/暂缓）只活在 PPT 里
- 方向：**A 指标阶梯**（派生指标树，抄写变引用）；**B 预算投放+达成率环比**；**C 口径就绪地图**（每指标声明就绪状态/卡点/负责人，报表页成色条）
- 首选：A——它是 B/C 的地基；把红线从文件级升级到公式级；不依赖任何外部输入

### 资深 ERP 实施顾问
- 缺口：①分摊是"数据"不是"规则"（分摊发生在底座外的 Excel/集成层，基数一变全线回炉——红线被上游架空，D12"零收入月均摊兜底"SQL 补丁已是症状）；②无调整凭证层（审计调整/红字冲销无处挂接，自动数与人工数不分离）；③级联零勾稽（"各级报表互相勾稽吗"是 UAT 第一问）
- 方向：**A 分摊规则引擎 allocation.yml**（发送方/接收方/基数/方向/循环顺序——第七块积木候选）；**B 调整凭证层 adjustments.yml**；**C 勾稽对账测试**（从 base 链自动生成平衡测试，零配置默认开）
- 首选：C——"先把算得对不对变成机器可证，再谈算得更细"；A 摊错、B 挂错全靠 C 报警；纯编译器生成、1~2 天量级

### 资深数据科学家/分析工程师
- 缺口：①carry 一律 sum 无类型系统（avg/半可加静默错误，证据：budget_rate 已在宽表）；②损益表达式复制 6 份无 derived（**字段级血缘碎掉的根因**）；③后代传导维度静默改粒度 + 层间守恒零测试（证据：L1 实际生成 SQL 按月份+项目+一级部门分组）
- 方向：**A 指标类型系统**（additive/semi_additive/ratio 上户口，非可加进级联即报错）**+ derived 指标**（expr 引用指标名，编译期展开成指标 DAG，血缘编译期生成）；**B 时间智能**（cumulative/yoy/mom 内置窗口，窗口列禁参与 carry）；**C 层间守恒测试 + 粒度契约**（上卷必须显式声明）
- 首选：A——类型信息是 B、C 的地基；"重构前后数值快照逐值相等"可立即自证零回归；与红线"口径唯一出处"同构

## 五、脚本运行视图选项 ★圈这里

现状：跑批历史详情已有节点表（单节点耗时）+ 日志尾 400 行；`data/runs/<run_id>_run_results.json` 有每节点精确 execution_time，`logs/run_*.log` 全量文本——**以下选项都不需要动引擎**。

| # | 形态 | 一句话 | 优点 | 成本 |
|---|---|---|---|---|
| **①** | **Gantt 瀑布图**（单次运行）：摄取/编译/dbt 三段泳道，节点按 execution_time 排时间轴，红黄绿着色，点节点看日志 | Airflow Gantt 明账版；"这次谁最慢、卡在哪"一眼可见 | 数据全现成，纯前端 ECharts | **小（约 1 天）** |
| **②** | **Grid 历史矩阵**：行=节点（或三步阶段），列=最近 N 次运行，格子=灯色 | Airflow Grid 明账版；"retail 这月第几次黄"一眼可见 | history_*.json 现成 | 小-中（1~2 天） |
| **③** | **血缘图运行态**：血缘页节点按最近跑批状态着色呼吸，与总览管道卡统一 | 图即状态，最直观 | G6 已有 80% | 中 |
| **④** | **实时日志流**：运行中逐节点滚动日志段 | 调试体验最佳 | 需后端日志分片 | 中-大 |

**主会话推荐**：**① 先做**（最缺的"单次运行内部视角"），**② 随后**（跨次趋势）；③ 顺手强化已有雏形；④ 缓。
