# app/ —— 门户

你在浏览器里看到的界面，加上背后支撑它的服务。地址 `http://127.0.0.1:8620`，只在本机监听。

- `main.py` — 装配入口：启动生命周期、缓存中间件、挂载路由与静态页（业务路由在 `routers/`）
- `routers/` — 六个域路由模块：portal（账套/总览/设置）、lineage（血缘/字典）、reports（报表/口径）、runs（跑批）、workbench（配置工作台）、open_api（钥匙鉴权的对外接口）；`deps.py` 是公共助手
- `config.py` — 全局路径与常量（版本号读仓库根 `VERSION`）
- `services/` — 后端各科室：跑批编排、配置工作台、中文别名层、设置存取、跑批调度
- `static/` — 网页本体（原生 JS + ECharts 图表 + G6 血缘图，无构建链）

## 为什么这样拆（2026-10-06 收纳，PR#6/#7）

main.py 曾是 835 行 30 路由平铺的单体。拆分不是为了好看，是三个实际原因：

1. **AI 定位代码的准确率**。本项目第一维护者是 AI agent，一个域一个小文件，agent 改报表接口时直接开 reports.py，不用在 835 行里搜——改错位置、改漏引用的概率随之下降。
2. **单一出处防漂移**。实例根路径曾三处各写一份、六份 yml 清单两处维护，将来加配置/改路径必然改一漏二。收敛后语义层 `semantic/loader.py` 是唯一出处，此处全部引用。
3. **给未来模块留落点**。登录、权限（规划 v0.7）落地时不往 main.py 里塞路由，而是按域加盒子或往对应盒子加——main.py 永远只做装配。

## 维护规则

- 新增接口放进对应域的盒子；新业务域建新盒子并在 main.py 挂载（注册顺序注意：同前缀的具体路径在前，静态挂载最后）
- 公共助手（异常翻译/当前账套/过期信息）只放 `routers/deps.py`，不在各盒子复制
- `runs/status` 必须注册在 `runs/{run_id}` 之前（路径参数会吞掉同缀具体路径）
- Response/JSONResponse/PlainTextResponse 从 `fastapi.responses` 导入，不从 `fastapi` 顶层（踩过）
- 只动结构不动行为的改动，用 `ops/api_diff.py` 拍改造前后快照自证（用法见文件头；非确定性端点用连拍两次后快照互比来甄别）
- 改 `static/` 下的文件必须同步升 `static/index.html` 里的 `?v=` 版本串，否则浏览器用旧缓存；改后端要重启门户才生效
